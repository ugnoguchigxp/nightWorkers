# NightWorkers 0.1.0 Release Notes

Release date: 2026-07-10

NightWorkers 0.1.0 establishes the local-first control-plane baseline: Project
registration, Workbench planning and execution, explicit Queue admission,
desktop packaging, and persisted evidence for implementation and review.

## Migration

Run `bun run setup` to install dependencies and apply the current SQLite
migrations. Existing local databases remain supported by the normal idempotent
migration path. Back up the runtime directory before moving a long-lived desktop
installation to this release.

## Rollback

Stop NightWorkers, restore the previous application artifact, and restore the
runtime directory backup taken before migration. Do not point an older binary at
a database after newer migrations have been applied unless that release's schema
compatibility has been verified.

## Known Limitations

- NightWorkers is a single-user local control plane, not a hosted collaboration
  service.
- Automatic PR creation, merge, deployment, and store submission are outside the
  0.1.0 release contract.
- Signing and notarization require platform credentials and are recorded in the
  artifact manifest when requested; they are not bypassed or simulated.

## Desktop Support Matrix

| Platform | Artifact | Minimum / target | Verification |
| --- | --- | --- | --- |
| macOS | `.app`, optional `.dmg` | macOS 12+ | build, sidecar smoke, packaged smoke; signing/notarization when credentials are supplied |
| Linux | `.deb`, `.rpm`, AppImage | x64 runner with system WebView dependencies | cross-platform readiness plus native build on Linux |
| Windows | NSIS, MSI | x64 Windows runner | cross-platform readiness plus native build on Windows |

## Artifact Integrity

Run `bun run verify:release` before creating a tag. After it passes, generate the
checksum and signing/notarization record with
`bun run release:manifest -- --artifact <path> --verification-status passed`.
The artifact filename, manifest version, and tag must all use `0.1.0` / `v0.1.0`.
